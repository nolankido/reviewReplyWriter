## Observed failure and repair

A controlled execution of the actual compose handler returned a saved draft,
then failed its separate library read. The draft was shown, but the final notice
contained only the read failure instead of “Draft saved.” This could leave an
owner uncertain whether generation had succeeded. It is a reproduced handler
defect, not a reported operator experience.

Generation, regeneration and explicitly opening a recovered generation now show
their acknowledged result before refreshing the library. If that separate read
fails, the notice retains the successful outcome and explains that the library
could not refresh. The saved result remains visible. Refresh the library later;
this warning does not request or perform another generation.

Template fallback wording still says it is not AI output. A recovered draft that
changed still says its current version changed. Genuine generation failures keep
the unresolved request check and current editor. Failed saved-draft lookups keep
the existing form and pending check. No result is treated as saved merely because
a request was sent. Policy confirmation, human approval, revision leases and
read-only result lookup retain their existing behavior. No new panel, dependency,
backend mutation or automatic retry was added.
